# LUMA / 15 — shared implementation contract

Target: ESP32 Dev Module (original ESP32/WROOM, not C3/S3). Preserve uploaded wiring: WS2812B 15 pixels GRB GPIO16; DHT11 GPIO4; LDR ADC1 GPIO34 (larger ADC = darker); MAX4466 ADC1 GPIO35; PIR GPIO27. Limit LED supply to 5 V / 800 mA in FastLED. No motors present. Default safe brightness 128. No runtime delay()/busy-wait loops; DHT11 use interrupt-edge capture and millis/micros state machine, not blocking DHT library. Separate Wi-Fi and animation/automation state machines. All times unsigned-wrap-safe.

## Source artifacts
`index.html`: standalone vanilla dashboard (also copied to `dashboard.html`). `firmware/LampuHiasPintar/LampuHiasPintar.ino`: complete sketch. `tools/embed_dashboard.py` embeds HTML as gzip PROGMEM in `firmware/LampuHiasPintar/dashboard.h`. Compile via Arduino CLI, ESP32 core 3.3.x. Firmware dependencies: FastLED, ArduinoJson 7. Use built-in `esp_http_server` on a dedicated server task, NOT the synchronous Arduino WebServer. REST request handlers enqueue changes into a bounded queue; only main loop owns application state; publish a synchronized status snapshot for HTTP. Do not perform network writes while holding a mutex. Serve HTTP from AP+STA with device-specific AP password printed on serial (>=12 chars), no open AP or embedded home credentials. Local/private device API; no cross-origin permissive CORS, same-origin POST JSON, reject foreign Origin. Hostname luma-15, persistent AP fallback.

## API
* GET `/`: gzip dashboard, Content-Encoding gzip.
* GET `/api/status`: full state below, version 1; JSON, no cache.
* POST `/api/config`: partial JSON config object; all-or-nothing validation (unknown keys/types rejected), at most 1024 bytes, range checks. Response 202 `{ "ok":true,"queued":true }`; poll confirms actual state. Failures 400/413/503 with `{ "ok":false,"error":"..." }`.
* POST `/api/action`: JSON `{ "action": "pomodoroStart"|"pomodoroPause"|"pomodoroResume"|"pomodoroReset"|"sleepStart"|"sleepCancel"|"save" }`; sleepStart uses configured sleepMinutes. No arbitrary extra action keys. Same queued response.
* POST `/api/time`: JSON `{ "epoch": integer Unix UTC seconds (1704067200..4102444799, 2024..2099) }`. Device receives browser time; timezone applied using config.utcOffsetMinutes. Browser polling never overwrites clocks; browser synchronization is explicit / initial connect when invalid. The ESP32 independently starts nonblocking SNTP against pool.ntp.org and time.nist.gov on station connection, adopting valid native UTC once per second as needed. Explicit browser sync also calls settimeofday to keep the native clock consistent. No RTC is present; if offline after reboot, scheduling safely gates off until browser sync.

## Config (identical keys in firmware / UI / simulation)
`power`:bool=true; `mode`:enum string manual|effect|temperature|music|auto|demo|circadian; `effect`:integer 0..11=0; `color`:string #RRGGBB=#c4b5fd; `brightness`:integer 0..255=128; `speed`:integer 1..100=35; `saturation`:integer 0..100=85; `reverse`:bool=false; `musicStyle`:enum bar|center|pulse=bar; `micGain`:integer 1..30=8; `motionHoldSec`:integer 5..600=45; `darkThreshold`:integer 0..4095=2000; `autoDim`:bool=true; `idleMinutes`:integer 0..120=0 (0 disables motion idle gating outside auto mode); `demoIntervalSec`:integer 5..120=15; `sleepMinutes`:integer 1..180=20; `wakeMinutes`:integer 0..60=10 (schedule fade-in duration, 0 immediate); `scheduleEnabled`:bool=false; `scheduleStart`:integer 0..1439=1080; `scheduleEnd`:integer 0..1439=1380 (start==end rejected, overnight belongs to start day); `scheduleDays`:integer 1..127=127 (bit0 Sunday); `utcOffsetMinutes`:integer -720..840=420; `focusMinutes`:integer 1..120=25; `breakMinutes`:integer 1..60=5. Deferred NVS writes (quiet period + minimum spacing), explicit save request, sanitize stored config on load. Temporary timer/pause state not persisted; settings retained. No telemetry fields writable.

Effects indices / labels: 0 Prism (rainbow), 1 Breath, 2 Aurora, 3 Meteor, 4 Ember (fire), 5 Tide, 6 Twinkle, 7 Spectrum, 8 Scanner, 9 Confetti, 10 Heartbeat, 11 Candle. Demo cycles all effects + temperature/music/auto in deterministic sequence; reports activeMode/activeEffect. Actual rendered frames sent in telemetry, no UI emulation of real device output.

## Status shape
`{apiVersion:1,revision:integer,config:{...all above},telemetry:{bootId:string,uptimeSec:number,freeHeap:number,minHeap:number,heapSize:number,rssi:number|null,wifiConnected:bool,ip:string,apIp:string,apClients:integer,clockValid:bool,epoch:number|null,temperature:number|null,humidity:number|null,dhtOk:bool,ldr:integer,micLevel:number 0..100,motion:bool,motionRemainingSec:integer,activeMode:string,activeEffect:integer,outputBrightness:integer,gateReason:string,pomodoro:{state:"idle"|"focus"|"break",running:bool,remainingSec:integer,durationSec:integer,sessions:integer},sleepRemainingSec:integer,dirty:bool,storageOk:bool,leds:[[r,g,b] x15]}}`. revision increments on applied config/actions/time updates. Gate reasons: power|schedule|clock|idle|sleep|active. Null sensor data must render unavailable, never invented readings. Missing clock when schedule enabled gates output off; explain in UI. Always use hardware reality in device mode. AP defaults shown as local info (no user-facing localhost preview links).

## UI
Design direction: bespoke graphite/cyan/lilac instrumentation dashboard, SVG lamp preview using actual LED samples, inline icons, responsive desktop/mobile, no external assets. Integrate every config and action, show all telemetry via concise HUD/detail cards. Explicit Simulation mode (`?demo=1` or file://) with visible badge and fake transport; never silently switch to simulation on network errors. UI should export a small testable `window.Luma` interface: `{getState(), patchConfig(patch), action(name), syncTime(), setSimulationSensor(patch)}`. DOM controls use data-config="key"; ranges live labels; schedule time inputs convert HH:mm to minutes, day controls build bitmask. Serialize commands, coalesce rapid range inputs, abort/time out requests, do not toast success before apply confirmation, disable controls until connected, retry polling with backoff, handle visibility, don't overwrite focused/dirty input while telemetry polls. Reduced-motion support. Local simulation must implement all settings with same gates/effects and actions, simulate clocks, Pomodoro/sleep/deferred save and all three music styles.
